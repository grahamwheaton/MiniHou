## Job order and merge boundaries

Use one scratch worktree and one commit series **per file job**, all from the same `native-head4` commit. An agent should edit its assigned original file and only its new child directory. Do not have multiple agents edit `nodes/mod.rs`, `ui/mod.rs`, or the same original shim. Merge each completed batch before branching the next dependent batch; rerun checks on the merged result.

**Specific risks to control:** `model.rs`, `fracture_tools.rs`, and `uv/unwrap.rs` contain relative parity fixtures; keep those test blocks in place unless paths are updated deliberately. Moving `element_select` or `sketch` tests changes their `include_str!` base directory. `network.rs`, `params.rs`, and `viewport_ui.rs` already use explicit `#[path]` modules; preserve those resolutions. Tests using `use super::*` will need explicit parent re-exports when private functions move. Node registrations must retain the same constants, parameter macros, cook signatures and output names. None of the listed target files appears to be generated, but app parameter metadata is loaded from the generated `param_meta.json`; this plan does not alter that artifact.
