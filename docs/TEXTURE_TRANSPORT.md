# Blender viewport texture transport (add-on 0.4.1)

## Design as built

The live link advertises `viewport_materials_v1` and `image_assets_v1`. Blender reads evaluated material slots on its main thread and sends a revisioned manifest before geometry. Object watches use `scope: "object:<name>"`; stack modifiers and Geometry Nodes placements use `scope: "instance:<id>"`. The receiver adds a connection namespace to material IDs, checks the geometry's `manifest_revision`, and writes the binding table into geometry detail. A later manifest updates the registry and GPU texture bindings without recooking geometry. Older peers retain their existing untextured path.

`material_manifest` contains `revision`, `scope`, `descriptors`, `bindings`, `images` (SHA-256 IDs of the encoded payloads), and `diagnostics`. The receiver answers with `image_request` containing only absent hashes. Blender sends `image_begin` (`transfer_id`, `hash`, `total`), one or more `image_chunk` frames (`transfer_id`, `hash`, `offset`, `total`, MHL1 `data` array of `|u1` bytes), then `image_end`. `image_ack` means hash, coverage, format and decoded size checks passed; `image_error` gives a reason. The receiver retains verified encoded hashes across TCP reconnects within the current app session. The add-on resends a manifest on reconnect, and only requested images are transferred. Image chunks are queued one per main-thread tick, after geometry/control work; the socket writer uses a bounded 64-frame queue. The receiver's reader uses a bounded 32-frame queue and processes transfer bytes on the link thread.

The material exporter follows the active Material Output through reroutes or a bounded simple group output to Principled BSDF Base Color. It accepts one direct Image Texture with default UV or a UV Map node, and aliases the active render UV name to `uv`. Repeat, extend, mirror and CLIP plus nearest/linear sampling are mapped to the registry schema. CLIP is approximated by clamp-to-edge: Blender's transparent-black border outside the UV square is not reproduced. External PNG/JPEG and packed PNG/JPEG are read as bytes; generated, painted and other decoded images are snapshotted to PNG from `image.pixels` without saving or packing the image. Blender's bottom-up pixels are flipped to top-row PNG. Linear colour pixels are encoded to sRGB for colour textures; Non-Color pixels bypass that conversion. Image payload identity is SHA-256 of transferred bytes; the registry uses its own canonical decoded-pixel ID after verification. Changes are compared by content hash, including dirty images and changed files, once per second.

Unsupported shader paths, missing images, UDIM, sequences, movies, non-opaque Principled Alpha, non-identity Mapping transforms (including rotation), and advanced interpolation yield a diagnostic in the texture inspector. OPAQUE materials may use a PNG with an alpha channel when the Image Texture Alpha output is unlinked and Principled Alpha is 1. A linked Principled Alpha socket or a value below 0.999 is rejected, with the material name, socket finding and render mode in the diagnostic. A transparency render mode alone does not reject an otherwise opaque material. The descriptor retains the constant base-colour factor. Missing or pending image payloads use the renderer's checker fallback. A supported image with missing UVs also uses the checker. Texture inspector shows registry status plus transport pending/unsupported diagnostics.

## Diagnostics

For the reported `imagepaste-261017-142014` plane, CLIP made the object export discard its image descriptor, leaving a valid constant white material and the inspector's `no image · 1x1 · neutral` line. The `Textured surfaces use full detail` line is normal viewport LOD behavior. Headless Blender 5.2 reproduces the modifier prefix with the plane's original single material and Principled Alpha 1.000; its PNG alpha channel does not trigger the alpha diagnostic. The historical instance diagnostic therefore cannot be attributed to the reported shader alone. It means the live instance manifest contained a different material/socket state when sent; the revised diagnostic names that material and its linked/value state. The instance uses its own `peer:instance` manifest and slot IDs; geometry material names resolve through the parallel `material_bindings.slots` table. The receiver now registers each descriptor independently, so one unsupported slot cannot prevent another valid slot in the same manifest from acquiring its image.

## Limits and validation

- At most 1 MiB of `|u1` data per chunk, 16,000,000 pixels per image, 256 MiB per encoded transfer and decoded image, and 512 MiB of concurrent transfer buffers. Offsets use checked addition; duplicate, overlapping, incomplete, overflowed or wrong-hash transfers are rejected before publication.
- PNG and JPEG are accepted. High-precision 16-bit/float source decoding is explicitly unsupported by the current renderer registry; this is an open precision gap. Packed non-PNG/JPEG and generated images use an 8-bit sRGB/linear PNG snapshot, so precision may be reduced. Images with more than 16 Mpx are rejected.
- The receive link thread verifies hash and decodes for validation before ACK. Registry publication and GPU upload currently occur on the UI thread; large texture updates can still stall a frame. The registry applies its existing CPU/GPU budgets and LRU policy. The session's encoded retained-hash cache is bounded to 512 MiB and evicts oldest entries; evicted bytes are re-requested on reconnect.
- Socket tests cover capability advertisement, missing-hash request, chunk transfer, ACK, reconnect deduplication, coverage/overlap and hash rejection, and revision ordering. Headless Blender tests exercise external, packed and generated images, a UV seam mesh, unsupported nodes, a changed generated image, proxy and instance channels against a freshly built `link_selftest`. The 0.4.1 modifier regression creates the reported plane and three-user material with CLIP and an RGBA PNG, checks both packed and external variants through `read_prefix`, `modifiers.pump`, instance cooking, geometry bindings and app registry image state, and checks real alpha rejection diagnostics. Blender 4.5, 5.0, 5.1 and 5.2 passed. Blender 4.3 is unavailable on this machine. A separate headless GPU test decodes an MHL1 seam mesh and transferred PNG through the registry and checks tolerant colour regions; it skips if no adapter exists. The tests do not prove a live Blender or MiniHou window.

## Open questions

The 8-bit PNG snapshot path needs a precision-preserving float/16-bit format, with declared linear-space storage and a matching registry API. Material group traversal is bounded and does not resolve arbitrary group inputs or shader mixes. Non-identity Mapping transforms need schema and renderer support. Transport diagnostics are visible as inspector text, without per-slot thumbnails; the renderer already reports GPU downsampling. Encoded-byte retention uses FIFO eviction and could use reference-aware LRU. The main-thread registry decode/upload needs a frame budget. Saved-document asset persistence and a single test combining actual Blender output with GPU pixel readback remain to be built and tested.

## Try it

Build the native app and install add-on 0.4.1 from this checkout. In Blender, give an evaluated mesh a UV layer and an opaque Principled material whose Base Color is linked directly to an Image Texture. Start the native link, then use that mesh as a watched `blender_object`, stack modifier input, or Geometry Nodes placement. Select Flat or Smooth shaded texture mode in MiniHou and open Texture inspector to see image and diagnostic status. Painting a generated image or changing an external PNG/JPEG should update watched objects on the next poll; modifier and GN instances update on their next evaluation. Older peers continue to show the untextured mesh.
